How the official shell drives it (read today, `sonic3air_web.html`):

- `sonic3air_web.js` is a **classic, non-modular** Emscripten script: a global `Module`, every runtime
  function a top-level `var`/`function`. `noInitialRun: true`; the shell calls `callMain()` itself.
- `loader.js` (file_packager output) preloads `sonic3air.data` into `/sonic3air/` and caches it in
  IndexedDB (`EM_PRELOAD_CACHE`).
- When the data is in, the shell mounts **IDBFS at `/sonic3air/savedata`**, `FS.syncfs(true)`,
  `FS.chdir('/sonic3air')`, creates `/sonic3air/___internal/`, and starts the game if
  `/sonic3air/savedata/Sonic_Knuckles_wSonic3.bin` exists; else it shows a file prompt that checks
  4 194 304 bytes and `"1563"` at 0x186 (serial `MK-1563`, Sonic & Knuckles).
- `audioremaster.bin`, when present in savedata, is symlinked to `/sonic3air/data/audioremaster.bin`.
- The game's own JS hooks (`ASM_CONSTS`): `FS.syncfs(false)` after it writes save data;
  `Module.onExit()` when the game quits; the in-game file manager (Options) calls
  `triggerFileSelect()` (with `window.__s3airFileUploadPath`), `window.fileManagerExportFile(path)`,
  `window.fileManagerPromptRename(...)`, and expects `Module._ImGuiFileBrowser_OnWebImportDone()`
  after an import.
- Exported: `Module.pauseMainLoop` / `resumeMainLoop`, `Module.SDL2.audioContext`, `FS_*` helpers.
  Imports `emscripten_start_fetch` and `emscripten_websocket_*` (update check / online features).
  No pthreads: no SharedArrayBuffer needed (it still runs under the launcher's COOP/COEP).

## Design

Package `@wasm-gaming/sonic3air-wasm`, engine id **`sonic3air`**, everything under
`dist/sonic3air/`, release archive `sonic3air.tar.gz` → `sonic3air/sonic3air/…` (the launcher's
`engines.json` shape). engine-specs `^0.5.1`, its runtime copied beside the SDK
(`localize-specs.mjs`, as every engine).

### Build: no compiler, a pinned download

`make build-upstream` → `scripts/fetch-upstream.mjs` (Node, no Docker):

1. Download the zip of the pinned tag (cached in `.tmp/`), **fail unless the sha256 matches**.
2. Extract `sonic3air_web.wasm`, `sonic3air.data` unchanged → `dist/sonic3air/`.
3. `loader.js` → `sonic3air.data.json`: the `loadPackage({...})` argument (file list + package
   size + uuid), parsed and checked against the size of `sonic3air.data`.
4. `sonic3air_web.js` → `sonic3air.js`, an ES module:
   `export default function createSonic3Air(Module) { <upstream JS verbatim> … }`, resolving with
   the runtime's handles (`FS`, `callMain`, `MainLoop`…) when the runtime is initialised — what
   Emscripten's `MODULARIZE` would have produced. No global `Module`, one instance per call, files
   located next to the SDK (`import.meta.url`). The script checks its anchors (`var Module=`,
   `run();` at the end, `ASM_CONSTS`) and fails if upstream's output stops matching.
   Risk: ES modules are strict mode; checked by booting it (if it breaks, fall back to a classic
   script wrapper with the same factory).

Upstream's code is never edited: the wrapper only scopes it.

### SDK: `Sonic3AirSDK` / `Sonic3AirPlay` (engine-specs `EngineSDKBase` / `EnginePlayBase`)

- `assets.rom` (required) — Sonic & Knuckles + Sonic 3, bytes or a thunk. Validated before boot:
  4 194 304 bytes and `MK-1563` at 0x180-0x189 (the shell's own check). Written to
  `/sonic3air/savedata/Sonic_Knuckles_wSonic3.bin`: no prompt, ever.
- `assets.audioremaster` (optional) — the remastered soundtrack (`audioremaster.bin` from the PC
  release or the web zip), written to `/sonic3air/data/audioremaster.bin`. Not downloaded by the
  SDK; nothing in the engine downloads it either (that was the shell's button).
- `storage.namespace` → OPFS `sonic3air/<namespace>/` (`storagePath`, as the other engines).
  `/sonic3air/savedata` stays in memory (no IDBFS); before `main()` the SDK restores the folder tree
  from OPFS, and mirrors back what changed — **when the game itself syncs** (its `FS.syncfs(false)`
  is wrapped), every 10 s, on pause, on page hide and on destroy. Files the mirror wrote and the game
  later deleted are deleted in OPFS too. Never mirrored: the ROM and `audioremaster.bin` (inputs the
  host owns; the launcher keeps them in the same folder) and logs. Emits `saves` like rsdkv5.
- `pause(owner)` / `resume(owner)` — `pauseMainLoop()` / `resumeMainLoop()` + the SDL
  `AudioContext`; one owner at a time, as rsdkv5. `mute()` as rsdkv5.
- The game's quit (`Module.onExit`) → the contract's `exit` event.
- The in-game file manager (Options → mods, save backups) works: the SDK defines the three window
  hooks while a session runs (own implementation: a file input writing into the FS, a download, a
  `prompt()` rename) and removes them on destroy. Imported files land in savedata, so they are
  mirrored to OPFS like the saves.
- Canvas: `mount(target)` as rsdkv5 (own canvas or a given one, `id="canvas"` for SDL), fitted 16:9
  in its box.
- Input: SDL2 reads keyboard and `navigator.getGamepads()` — physical pads and the engine-specs
  touch pad need no bridge. The keyboard is the game's own mapping (checked during verification
  against the other Sonics' A/S/D; changed only through the game's own input config if needed).
- Not restartable in process (one `main()` per page), like rsdkv5: `restart()` / a second `start()`
  throws with that reason.
- Network features as upstream (it may try its update check); recorded what it actually does
  during verification.

### Engine app — `app/app.js` (`EngineApp`)

Boot screen → the game with its own title / save select / options → pause menu on the usability
scheme (UX.md): **Continuar**, **Volver al lanzador** (confirm, defaulting to "Seguir"). The game's
own exit leaves too. No save states (the engine has none to expose). Same structure and CSS as
rsdkv3's app.

## 2026-11-16 01:20 — Spike findings (headless Chromium, the owner's `Sonic_Knuckles_wSonic3.bin`)

Adds: what a minimal boot of the generated factory showed, and one change to the wrapper.

- The factory boots as an ES module (strict mode is fine): disclaimer → SEGA logo, WebGL (ES 2.0),
  60 frames/s on `requestAnimationFrame`, `AudioContext` running. The ROM written to
  `/sonic3air/savedata/` is picked up with no prompt (`RomPath` in `settings.json` points there).
- The game creates `settings.json`, `settings_input.json` and `logfile.txt` in savedata at boot and
  calls `FS.syncfs(false)` twice while doing it — the hook the save mirror uses works.
- **No external requests and no WebSocket** in the first 15 s. `settings.json` has
  `GameServer.ServerAddress: sonic3air.org` (ports TCP 21095 / UDP 21094 / WSS 21096),
  `GhostSync.Enabled: false` and `UpdateCheck.ReleaseChannel: 0`: online features are off unless the
  player turns them on in the game's options. Left as upstream.
- **Pause bug, fixed in the wrapper:** upstream links with `EXIT_RUNTIME` (`noExitRuntime=false`).
  `pauseMainLoop()` makes the stale runner drop the runtime keep-alive, the counter hits 0, the
  runtime exits and the game never resumes (seen: frozen after `resumeMainLoop()`). The official
  shell never pauses, so it never shows. The factory now sets `noExitRuntime = true` after the
  upstream code (same function scope; anchor `var noExitRuntime=false;` asserted) — Emscripten's
  default. Checked: 61 frames in 1 s → 0 while paused → 61 after resume. The game's own quit still
  reaches `Module.onExit` through its explicit `EM_ASM` hook.

## 2026-11-16 01:45 — Walkthrough: Phase 1 implemented and verified

Adds: what was built, how it was checked, and what is left. Nothing released yet (version `0.0.0`
on the branch; the first release bumps it to 0.1.0).

### What was built

- **`scripts/fetch-upstream.mjs`** (`make build-upstream`). It downloads the pinned zip, cached in
  `.tmp/upstream/<tag>/`, and fails on a SHA-256 mismatch. It extracts four files, writes
  `sonic3air.data.json` from `loader.js` (checking the file list is contiguous and the sizes match)
  and generates `sonic3air.js`. All anchors are asserted. The parse and wrap functions are exported
  for the tests, and errors are thrown (the CLI exits with 1).
- **The factory** (`sonic3air.js`). Upstream's script is copied verbatim inside
  `createSonic3Air(moduleArg)`. It resolves on `onRuntimeInitialized` with `Module` plus
  `FS` / `MainLoop` / `callMain`, rejects on abort, and sets `noExitRuntime = true` after the upstream
  code (the pause fix, see the spike findings).
- **`src/sonic3air.options.ts`**:
  - `SONIC3AIR_SPEC` lists config (`jsUrl`, `wasmUrl`, `dataUrl`), assets (`rom`: `.bin` / `.md` /
    `.gen`; `audioremaster`: `.bin`) and storage (`namespace`, `persist`).
  - Event: `saves { files, removed }`.
  - `SONIC3AIR_VIDEO` (16:9).
- **`src/sonic3air.sdk.ts`** (`Sonic3AirSDK` / `Sonic3AirPlay`):
  - Also exports `storagePath`, `checkRom`, `isMirrored`, `ROM_FILE`, `ROM_SIZE` and
    `AUDIO_REMASTER_FILE`.
  - Boot order:
    1. Validate the ROM, before any download.
    2. Fetch the data package and its JSON while importing the factory.
    3. Unpack the data, then create `savedata` and `___internal`.
    4. Restore the save data from OPFS.
    5. Write the ROM, and `audioremaster.bin` if given.
    6. Wrap `FS.syncfs` so it also flushes the mirror.
    7. Install the file-manager hooks, `chdir('/sonic3air')`, then `callMain()`.
  - Mirror: a recursive walk keyed by size + mtime. A flush asked for while another runs is coalesced
    into one more run. Deletions are mirrored. Triggers: the game's sync, every 10 s, pause, hidden,
    `pagehide` and destroy.
  - The game's `onExit` triggers `destroy()`, which emits `exit`. An abort while running emits
    `error`.
- **`src/app/app.js` + `app.css`** (rsdkv3's app structure, `s3air-` classes):
  - Screens: boot, game, pause (Continuar / Volver al lanzador), confirm, error (with the SDK's reason).
  - On touch, a ❚❚ button (top centre, safe-area aware) appears after the first touch and hides on a
    key press.
- **Demo pages**: `index.html` (the SDK, with `?ns=` for the storage namespace) and `app.html` (the app
  with `createInput()`).
- **Tests** (`node --test`, 27, synthetic data only): `storagePath`, the spec, `checkRom` (OK, empty,
  2 MB, wrong serial, wrong size), the mirror's exclusions, the loader parse and wrap (two isolated
  instances, nothing on the global object, a changed upstream refused), the built artifacts when
  present, and the app's exports.
- **`scripts/smoke-test.cjs`** (`make smoke ROM=… [AUDIO=…] [SHOTS=…]`): runs headless Chromium
  against `dist/`, as below.
- **Repo files**: `Makefile`, `tsconfig.json`, `package.json` (GPL-3.0-or-later, engine-specs
  `^0.5.1`), `LICENSE` (GPLv3), `THIRD_PARTY_NOTICES.md` (S3AIR, SDL2 2.32.8, Dear ImGui 1.92.4,
  ProggyClean, with the corresponding source at the tag), `README.md` (Project Specs, Todos).
- **CI**:
  - `build.yml`: build + test with the upstream zip cached; Pages on main.
  - `release.yml`: version stamp, build + test, npm publish with provenance, then
    `sonic3air.tar.gz` / `.zip` checked for the SDK, factory, wasm, data, contract runtime, app and
    LICENSE.
